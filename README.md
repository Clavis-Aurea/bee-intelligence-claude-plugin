# Bee Intelligence plugin

Agent (`bee-assistant`) and skills for Bee Intelligence (Beetrack). The plugin connects to one Beetrack site's MCP: `https://<site>.beetrack.vn/bi/rest-api/mcp`.

## Install
Add this repo as a marketplace, then install `bee-intelligence`. When prompted, enter the **Beetrack site**: the subdomain only (e.g. `acme`).

Authentication uses OAuth, no token needed: run `/mcp`, select `bee-intelligence` and sign in with your Beetrack account in the browser. The tools available depend on that user's permissions.

## Privacy
See the [Privacy Policy](https://github.com/Clavis-Aurea/bee-intelligence-claude-plugin/blob/main/PRIVACY.md).

## Uploading files
The `bee-upload-file` skill uploads a local file into an organization folder, using `scripts/upload-org-file.mjs` (generated by the bi CI, do not edit). It needs Node.js 20+ or Bun on the PATH.

## Revenue management skills
The `bee-rm-*` skills make `bee-assistant` a hotel revenue manager assistant: daily review, monthly review, P&L analysis (USALI), forecast, pricing, group displacement, GOP optimization, guest insights, F&B, and data audit. Shared rules and KPI definitions are in `context/revenue-management.md`. Metrics defined in Bee Intelligence take precedence over those definitions, and every norm or target comes from the user, per hotel, never from the reference values.

The `bee-rm-analyst` agent is an internal sub-agent the skills use for heavy data work (many hotels, large raw data). It is not meant to be used directly: it refuses any input that isn't a delegation brief from `bee-assistant`. Claude Code has no setting that hides a plugin agent, so this is enforced by the agent's own instructions.

## Decisions and norms
Confirmed decisions (e.g. "revenue excludes VAT"), the list of hotels, and per-hotel norms are saved in Claude's memory or the Bee Intelligence Glossary, whichever the user chooses the first time. `bee_config` is not used for them.

## Project config (optional)
`.bee/bee_config.json` in the project folder (schema and example in `context/`) is reserved for project settings and currently holds only `version`. No credentials.

## Personal settings (optional)
Create `SOUL.md` / `USER.md` in the plugin data folder (`~/.claude/plugins/data/<id>/`) from the templates in `context/`. They survive plugin updates.
